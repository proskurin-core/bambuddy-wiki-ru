# Панель администратора {#admin-panel}

`http://bambuddy.local:8001`, пользователь `admin`, пароль задаётся в мастере настройки.

Панель управляет **устройством**. Настройки самого Bambuddy находятся внутри приложения на порту `8000`. Разделение сделано намеренно: панель работает как независимая служба и остаётся доступной, когда Bambuddy перезапускается, настроен неправильно или вообще не запускается.

!!! warning "Обычный HTTP в доверенной локальной сети"
    Как и сам Bambuddy, панель использует обычный HTTP с аутентификацией HTTP Basic. В HTTP учётные данные Basic передаются в кодировке base64, но не шифруются. Используйте устройство в доверенной сети или настройте перед ним собственный обратный прокси.

    Если пароль не задан, панель отклоняет все запросы, кроме `/health`, с кодом `503`. Благодаря этому по умолчанию она может безопасно слушать все интерфейсы.

## :material-view-dashboard: Dashboard {#dashboard}

Состояние устройства на одном экране:

- **Температура процессора** и признаки питания и перегрева Raspberry Pi: пониженное напряжение и ограничение частоты *сейчас* и *с момента загрузки*. Последние помогают объяснить неожиданные замедления; их может вызвать дешёвый блок питания USB-C.
- Использование **диска и памяти**.
- **Контейнеры** Bambuddy и его базы данных, их состояние и работоспособность, а также состояние соответствующих служб.
- **Сеть**: имя хоста, имя mDNS и все адреса устройства.
- **Оборудование**: плата, память, объём карты, блок питания и наличие охладителя.
- **Лицензия**: состояние, редакция (Personal, Lifetime или Business), дата окончания обновлений и оставшиеся дни. Для Lifetime показано «No end date» без обратного отсчёта. У устройства без ключа указано «not applicable»; при отказе регистратора отображается причина и кнопка **Enter a key**.
- **Версии** ОС, компонентов устройства и работающего контейнера Bambuddy.

![Dashboard](../assets/appliance-panel-dashboard.jpg){ .screenshot }

Здесь также есть кнопки корректной **перезагрузки** и **выключения**. Пользуйтесь ими вместо отключения питания: прерывание записи на SD-карту — частая причина выхода устройства из строя.

### Bambuddy Backup {#bambuddy-backup}

Резервные копии Bambuddy, сохранённые на устройстве, перечислены от новых к старым с датой, размером и кнопкой **Download**. Это копии, создаваемые в Bambuddy через **Настройки** &rarr; **Резервное копирование** &rarr; **Резервные копии по расписанию**, по расписанию или по кнопке запуска. Пока копий нет, карточка подсказывает, где их создать.

Панель продолжает работать при недоступности Bambuddy, поэтому через неё можно скачать данные, если приложение не запускается, например после неудачного обновления. Скачайте копию перед сбросом или повторной записью образа и храните её вне устройства: копия на той же SD-карте будет потеряна вместе с ней.

!!! info "Доступ к данным сохраняется"
    Карточка работает и на устройстве, срок обновлений которого истёк или регистрация которого отозвана. Обновления и действия управления прекращаются, но резервные копии остаются доступными для скачивания.

### Контейнеры {#the-containers}

Устройство запускает два контейнера: Bambuddy и его [PostgreSQL](index.md#the-database). Карточка Services показывает оба, поскольку состояние служб не даёт полной картины: `bambuddy.service` сообщает о запуске Docker Compose и остаётся активной, даже если база данных постоянно перезапускается. Контейнер, который работает, но не проходит проверку работоспособности, отображается соответственно.

Кнопка **Restart Bambuddy** рядом с Reboot и Shutdown перезапускает оба контейнера вместе. По отдельности их перезапускать нельзя: они запускаются в определённом порядке, и при перезапуске половины стека Bambuddy может обратиться к ещё недоступной базе.

!!! info "Управление контейнерами намеренно ограничено"
    Здесь нет списка всех контейнеров, их остановки, удаления или оболочки. Назначение устройства — избавить владельца от такого администрирования; эти экраны отвечают на основные вопросы: работает ли система и почему нет.

### Проверка оборудования {#the-hardware-check}

При каждой загрузке плата, память, карта и блок питания проверяются на соответствие требованиям устройства; результат отображается на Dashboard.

Результаты имеют два уровня. **Предупреждение**, например о пониженном напряжении с момента загрузки или отсутствии охладителя, носит рекомендательный характер и ничего не меняет. **Блокировка**, например для Pi 4, 2 ГБ памяти или карты 32 ГБ, означает, что Bambuddy вообще не запускается: такие проблемы могут проявиться лишь через месяцы замедлением, износом карты или потерей истории печати.

!!! warning "Блокировку можно обойти, но панель продолжит предупреждать"
    Баннер позволяет всё равно запустить приложение. Bambuddy будет работать на неподдерживаемом оборудовании, а панель продолжит показывать жёлтое предупреждение, пока действует обход. Иначе о нём легко забыть и через год принять его последствия за ошибки Bambuddy.

## :material-lan: Network {#network}

**LAN connection** показывает активный интерфейс и его адреса.

**Secondary IP aliases** добавляет адреса к интерфейсу локальной сети: по одному для каждого [виртуального принтера](../features/virtual-printer.md), которому нужен собственный адрес.

```bash
bambuddy-appliance net-alias-add 192.168.1.50/24
```

Адреса добавляются *наряду* с основным адресом DHCP. Основной IP, DHCP и шлюз намеренно не изменяются, поэтому с этого экрана нельзя случайно отключить устройство от сети.

![Сеть](../assets/appliance-panel-network.jpg){ .screenshot }

**Tailscale** подключает устройство к вашей сети tailnet, чтобы обращаться к нему и его виртуальным принтерам откуда угодно без открытия порта маршрутизатора. Демон включён, но по умолчанию вход не выполнен. Панель запускает `tailscale up`, показывает URL входа и QR-код; первоначальная регистрация выполняется на странице Tailscale, поэтому консоль и ключ API не нужны. Затем показывается адрес tailnet `100.x`, который можно вставить в слайсер.

## :material-update: Updates {#updates}

Три независимых направления показывают текущую и последнюю версии.

![Обновления](../assets/appliance-panel-updates.jpg){ .screenshot }

### Bambuddy {#bambuddy}

Загружается выбранный тег контейнера, обновляется зафиксированная версия в файле Compose, контейнер запускается и проверяется работоспособность Bambuddy.

!!! success "Автоматический откат"
    Если новая версия не проходит проверку, устройство возвращает и перезапускает предыдущий тег. Обновление не затрагивает данные: меняется только образ контейнера.

**Check for updates** запрашивает последний тег релиза в реестре контейнеров и заранее заполняет поле.

### Компоненты устройства {#the-appliance-layer}

Мастер настройки, панель администратора, CLI, службы systemd и конфигурация шлюза — всё, что окружает Bambuddy. Нажмите **Check for updates**, затем **Update appliance**: установка выполняется на месте без перезагрузки и записи SD-карты.

Это подписанный пакет Debian из собственного репозитория Bambuddy. Результат проверяется так же, как при обновлении Bambuddy. Если после него Bambuddy не запускается, восстанавливается предыдущая версия компонентов.

!!! info "Нужна действующая лицензия"
    Репозиторий выдаёт пакет только зарегистрированному устройству с действующей лицензией. Устройство с истёкшей или отозванной лицензией продолжает получать обновления безопасности Debian, поскольку эта часть репозитория открыта всем, но обновления компонентов устройства недоступны. См. [Регистрация](registration.md).

Свежезаписанная карта также один раз обновляет компоненты при первой загрузке с сетью, чтобы старый образ не оставался устаревшим.

### Операционная система {#operating-system}

Обновление пакетов Debian (`apt full-upgrade`) с предварительной проверкой свободного места и часов.

!!! danger "Откат обновления ОС невозможен"
    В отличие от обновления Bambuddy, обновление ОС нельзя отменить. Оно не запускается при свободном месте менее 1 ГБ, предупреждает о несинхронизированных часах и сообщает, когда нужна перезагрузка. Сначала создайте резервную копию.

### Оба направления {#both-lanes}

Задания обновления выполняются независимо от панели. Закрытие вкладки браузера или даже перезапуск панели во время обновления их не прерывает: прогресс записывается в файл, который опрашивает страница. Откройте вкладку снова, чтобы продолжить наблюдение.

### Для чего всё ещё нужна новая карта {#what-still-needs-a-new-card}

Компоненты устройства обновляются отдельно, поэтому повторная запись образа нужна для нижележащих частей: ядра, прошивки и разметки разделов. О последствиях см. [Обновления и резервные копии](updates.md).

## :material-stethoscope: Diagnostics {#diagnostics}

Просматривайте журнал любой основной службы — Bambuddy, Docker, панели администратора, мастера настройки или firstboot — **либо журнал любого из двух контейнеров**. База данных пишет журнал в Docker, а не в системный журнал, поэтому ошибки её запуска доступны только здесь.

Оба списка фиксированы. Панель никогда не передаёт заданное пользователем имя в `journalctl` или `docker logs`.

![Диагностика](../assets/appliance-panel-diagnostics.jpg){ .screenshot }

**Download support bundle** собирает в один ZIP сведения хоста: данные системы, журналы служб и **обоих контейнеров**, вывод `docker compose ps`, `docker ps`, `ip addr` и `ip route`, а также файлы конфигурации устройства.

!!! info "Учётные данные удаляются"
    Секретные значения в `bambuddy.env` маскируются, а хеш пароля администратора и ожидающие применения учётные данные Wi-Fi никогда не включаются. Пакет можно прикрепить к публичному сообщению об ошибке.

Это дополнение на стороне хоста к пакету поддержки самого Bambuddy со страницы **Система**. Для качественного отчёта обычно нужны оба пакета.

## Настройка панели {#customising-the-panel}

На странице есть переключатель светлой и тёмной темы и выбор языка из тех же десяти вариантов, что и в мастере настройки.

Переопределения оператора находятся в `/etc/bambuddy/admin.env`:

```bash
# Bind loopback-only and front it with your own reverse proxy
BAMBUDDY_ADMIN_BIND=127.0.0.1
BAMBUDDY_ADMIN_PORT=8001
```
